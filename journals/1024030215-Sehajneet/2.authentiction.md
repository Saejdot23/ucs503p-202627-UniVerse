# Authentication, User Management & Utilities

## Authentication Implementation

### Objective

The primary goal was to implement the **authentication and user-management foundation** of UniVerse and connect it with the project structure established during the initial setup.

The focus was on implementing Google-based authentication, securing API routes, managing user sessions through tokens, and building the initial user profile functionality.

---

# Google OAuth Authentication

Google OAuth authentication was implemented to provide a simple and secure login mechanism for UniVerse.

The implementation included:

* Integrating **Google OAuth** for user authentication.
* Implementing the Google login flow.
* Handling the OAuth callback.
* Restricting authentication to **`@thapar.edu` email accounts**.
* Creating or retrieving the corresponding user from the database after successful authentication.

This establishes the primary authentication mechanism for UniVerse while ensuring that the platform remains limited to the intended student community.

---

# JWT-Based Authentication

After successful Google authentication, **JWT-based authentication** was implemented to manage authenticated sessions within the application.

The backend now supports:

* Generating access tokens for authenticated users.
* Verifying access tokens through authentication middleware.
* Implementing refresh-token support.
* Protecting routes that require authentication.
* Implementing logout functionality.
* Providing an endpoint to retrieve the currently authenticated user.

This creates a protected backend structure where user-specific functionality can be accessed only after authentication.

---

# User & Skill Models

The initial user-management database models were implemented using **Mongoose**.

### User Model

The User model was created to store information associated with each UniVerse user, including their authentication and profile-related data.

### Skill Model

A separate Skill model was also created to represent the skills that users can associate with their profiles.

This provides the database foundation required for the future **skill discovery, mentorship, and matching** functionality.

---

# Profile Management

Basic user profile functionality was implemented.

The backend now supports:

* Updating user profile information.
* Managing user avatar/profile pictures.
* Associating users with their skills.
* Retrieving authenticated user information.

These features establish the foundation for the user profiles that will later be used for skill discovery and community interactions.

---

# Avatar Upload & Cloudinary Integration

Profile-picture uploading was implemented using **Multer and Cloudinary**.

The upload flow includes:

1. Receiving the avatar file through the API.
2. Processing the uploaded file using **Multer**.
3. Uploading the image to **Cloudinary**.
4. Storing the resulting image URL with the user's profile.

This allows user avatars to be stored using cloud-based image storage rather than relying on local server storage.

---
