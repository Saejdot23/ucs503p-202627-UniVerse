---

# 2. User Management

## 2.1 User Profile API

Implemented the user profile functionality in:

`code/backend/src/controllers/user.controllers.js`

### Endpoint

`GET /api/v1/users/:username`

### Functionality

- Finds a user using their unique username.
- Excludes sensitive authentication information such as `refreshToken` and `googleId`.
- Populates the user's skills to teach and skills to learn with their name and category.
- Counts completed sessions in which the user participated as either mentor or learner.
- Returns a structured API response.
- Returns a 404 error when the requested user does not exist.

---

## 2.2 User Search

Implemented user search functionality.

### Endpoint

`GET /api/v1/users`

### Supported filters

- Username
- Full name
- Branch
- Year
- Page
- Limit

The username and full-name search is case-insensitive.

The response includes:

- Full name
- Username
- Avatar
- Branch
- Year
- Average rating
- Total ratings
- Skills to teach
- Skills to learn

Pagination was implemented using page and limit values. Users are sorted by average rating in descending order.

---

## 2.3 Saved Posts

Implemented functionality for saving and removing saved posts.

### Save a post

`POST /api/v1/users/saved/:postId`

The controller:

1. Checks whether the post exists.
2. Checks whether the post has already been saved.
3. Prevents duplicate saves.
4. Adds the post using MongoDB's `$addToSet`.

### Unsave a post

`DELETE /api/v1/users/saved/:postId`

The post is removed from the user's saved-post list using `$pull`.

### Retrieve saved posts

`GET /api/v1/users/saved`

This endpoint:

- Retrieves the authenticated user's saved post IDs.
- Fetches the corresponding posts.
- Populates the post author information.
- Supports pagination.
- Sorts posts by creation date.

---

## 2.4 Credit History

Added the credit history route to the user router.

### Endpoint

`GET /api/v1/users/credits/history`

The route uses the existing credit service to retrieve the authenticated user's credit history and supports pagination through `page` and `limit`.

The response follows the project's standard `ApiResponse` structure.

# 3. User Routes

Implemented:

`code/backend/src/routes/user.routes.js`

The routes added are:

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/v1/users/` | Search users |
| GET | `/api/v1/users/saved` | Retrieve saved posts |
| POST | `/api/v1/users/saved/:postId` | Save a post |
| DELETE | `/api/v1/users/saved/:postId` | Unsave a post |
| GET | `/api/v1/users/credits/history` | Retrieve credit history |
| GET | `/api/v1/users/:username` | View a user profile |

The router applies `verifyJWT`, so the user routes require authentication.

The credit-history route is placed before `/:username` so that `credits/history` is not interpreted as a username.

# 5. Technical Issues and Resolutions

## 5.1 Nodemon Module Error

### Problem

While starting the backend development server, Nodemon produced a module-resolution error:

```text
Cannot find module '../lib/cli'
```

This prevented the development server from starting correctly.

### Resolution

The local Node dependencies were cleaned and reinstalled. The problematic `node_modules` installation and lockfile were removed before reinstalling the project dependencies.

After reinstalling, Nodemon was correctly installed and the development server started successfully.
